# UCAM Portal Scraping Contract

The scraping layer (`scraper/extract_ucam.py`) extracts class schedules and attendance records from the American International University / NITER UCAM portal (ASP.NET WebForms + SSRS ReportViewer). This document defines the live DOM contract, selector invariants, capture procedures, and fixture policies.

## 1. Authentication and Entry Points

- **Login URL:** `https://ucam.niter.edu.bd/Security/LogIn.aspx`
- **Controls:**
  - Username input: `#logMain_UserName`
  - Password input: `#logMain_Password`
  - Submit button: `#logMain_Button1`
  - ASP.NET form state: `__VIEWSTATE`, `__EVENTVALIDATION`
- **Cloudflare Interstitial:** The login portal serves Cloudflare challenge pages (`Just a moment...`). The extractor executes an offscreen warmup navigation to `https://www.google.com` followed by bounded polling on `#logMain_UserName`.
- **Headless Runtime Invariant:** Headless scraping must run via `xvfb-run` with a standard desktop viewport (`1920x1080x24`). Do not attempt pure headless flags (`--headless=new`) without a virtual frame buffer; probe scripts that bypass `xvfb-run` stall at the Cloudflare interstitial.

## 2. Post-Login Navigation

Navigation utilizes fixed internal module menu identifiers (`mmi`) established by the portal shell:

- **Student Dashboard:** `/Module/Dashboard/StudentDashboard.aspx?mmi=41485d2c6c554d494e63`
- **Class Routine Report:** `/Module/schedular/Report/RptStudentClassRoutine.aspx?mmi=40545e1e42555f594e63`
- **Class Attendance Dashboard:** `/Module/Dashboard/StudentClassAttendanceDashboard.aspx?mmi=40545a1b42555b5c4e63`

The query parameter `mmi` represents an access token generated by the portal router; URLs must be visited verbatim.

## 3. Semester Selection and Postbacks

Both the routine and attendance dashboards dynamically load semester data through a dropdown control:

- **Selector:** `#ctl00_MainContainer_ddlHeldIn`
- **Options:** Value `0` is the `"Select"` placeholder. The first option where `value != "0"` represents the current active academic term.
- **Trigger:** Changing the selection requires invoking `onchange()` and dispatching a bubbling `change` event to initiate ASP.NET's `__doPostBack('ctl00$MainContainer_ddlHeldIn', '')`.
- **No Submit Button:** The attendance interface does not provide a form submission button. The visible text `"Search"` corresponds to client-side input `#txtSearchAttendance` (a course filter). The dropdown postback is the sole trigger for table generation.

## 4. Routine Report Shape (SSRS ReportViewer)

The class routine is rendered inside Microsoft SQL Server Reporting Services (SSRS):

- **Outer Wrapper:** `#ctl00_MainContainer_ReportViewer1_fixedTable`
- **Nesting:** Contains up to 23 levels of layout tables.
- **Data Table:** The data table possesses attribute `cols="9"` and an unstable generated class hash (e.g., `A306959b99...`). Never select or bind to class hash names.
- **Header Selection:** The table is identified by inspecting rows where cells contain the normalized subset: `course`, `course title`, `day`, `time slot`.
- **Row Structure:**
  - Row 0: Width spacer row containing blank cells (skipped).
  - Row 1: Header row mapping column positions.
  - Data Rows: Courses spanning multiple weekly sessions utilize `rowspan="2"` on `Course` and `Course Title`. Subsequent continuation rows contain only 7 cells (`Teacher`, `Contact`, `Day`, `Room`, `Time Slot`, `Section`).
- **Rowspan Expansion:** The parser expands `rowspan` and `colspan` into a uniform rectangular 2D matrix before index mapping so continuation rows retain their course code and title without column shifting.
- **Unscheduled Project Rows:** Senior project entries (e.g., `CSE-4114 Project`) omit day and time values. The parser filters rows lacking valid weekday cells.

## 5. Attendance Grid Shape

The attendance module displays course-level attendance records:

- **Grid Container:** `#ctl00_MainContainer_gvCourseList`
- **Rendering Condition:** The table does not exist on initial page load (placeholder `"Loading attendance details..."`). It renders approximately 3–5 seconds after the semester postback resolves.
- **Columns (5-Column Layout):**
  1. `SL#`: Sequence number.
  2. `Course Information`: Course code (`[A-Z]{2,4}-\d{4}`), course title, credit, and optional section label (`Section: [A-Za-z]\d?`).
  3. `Schedule One`: Slot 1 schedule summary.
  4. `Schedule Two`: Slot 2 schedule summary.
  5. `Attendance Information`: Structured attendance summary (`Present: X.XX% Total: N Classes [Status]`).
- **Count Derivation:** Portal attendance text provides percentages and total classes (e.g., `Present: 37.50% Total: 8 Classes Dis-Collegiate (DC)`). Attended classes are computed via `round(total * percentage / 100)`. Derived counts match the primary dashboard cards (`P: X`, `A: Y`, `Total: N`).
- **Status Normalization:** Portal status strings (`Dis-Collegiate (DC)`, `Non-Collegiate (NC)`, `Collegiate`) are normalized to `Dis-Collegiate`, `Non-Collegiate`, or `Collegiate`. Empty parentheses `()` default to `Collegiate`.

## 6. Failure Modes and Guardrails

- **Missing Attendance Grid:** If `#ctl00_MainContainer_gvCourseList` fails to render within 45 seconds of the postback, the scraper logs a warning and proceeds with routine publication. Missing attendance never aborts routine extraction.
- **Empty Parse Detection:** If the grid renders rows but the parser extracts 0 records, a warning is emitted logging the raw row count to detect layout changes.
- **Missing Semester Dropdown:** If `#ctl00_MainContainer_ddlHeldIn` is absent, routine extraction falls back to the existing DOM body.
- **Phone Normalization:** Teacher contact strings in international format (`+8801XXXXXXXXX` or `8801XXXXXXXXX`) are normalized to the standard 11-digit local format (`01XXXXXXXXX`).

## 8. Live Re-Capture Procedure

When the portal UI changes, capture fresh reference artifacts using a single browser session:

1. Launch Xvfb virtual display:
   ```bash
   xvfb-run --auto-servernum --server-args="-screen 0 1920x1080x24" bash
   ```
2. In one uninterrupted script, log in once, navigate sequentially across target pages, and capture DOM snapshots into `/tmp`:
   - Visit login -> authenticate.
   - Visit routine URL -> trigger semester change -> wait for weekday cell -> dump `routine_live.html`.
   - Visit attendance URL -> wait for `#ctl00_MainContainer_ddlHeldIn` -> trigger semester change -> wait for `gvCourseList.rows.length > 1` -> dump `att_live.html`.
   - Close the browser session.
3. Never launch separate browser processes per page; rapid session restarts trigger Cloudflare verification loops.

## 9. Fixture Sanitization Checklist

Before committing any captured DOM snapshot to `scraper/tests/fixtures/`:

- Replace student names and roll numbers (`SAMPLE STUDENT`, `CS 0000000`).
- Replace teacher names, initials, phone numbers, and emails with placeholders (`AB_Sample Teacher`, `01000000000`, `sample.teacher@example.test`).
- Retain exact HTML nesting depth, `cols="9"`, `rowspan`, `colspan`, header casing, and empty cell structures.
- Verify sanitization with regex checks:
  ```bash
  grep -nE '[0-9a-f]{32}|01[0-9]{9}|\+880|@' <fixture-file>
  ```
  Ensure all matches correspond strictly to dummy placeholders (`01000000000`, `example.test`).
